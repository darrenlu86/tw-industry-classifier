# 名冊維護與爬蟲

`data/authority_master.csv`（金管會權威名冊，1,343 列）是金融四類分類的事實來源，
**不是公開下載檔**。這份文件說明它怎麼來、怎麼更新，以及**更新流程裡有一段人工步驟**。

---

## 先講最重要的一件事

> **爬蟲不會自動更新 `authority_master.csv`。**
>
> 六支爬蟲的工作是「抓最新官方名冊 → 與既有快照比對 → 產出異動報告」。
> 從異動報告到 `authority_master.csv` 之間，有一段**人工歸併**：
> 判斷新增／更名／併購／退場、補統編、決定 segment 歸屬。
> 這一段目前沒有自動化路徑。

所以請不要對外承諾「每季自動更新」。實際能承諾的是：

- ✅ 每季**自動抓到**最新官方名冊，並自動告訴你「哪幾家新增、哪幾家不見了」
- ⚠️ 把異動反映進名冊，需要人看過並決定（約半天工作量，取決於異動筆數）
- ✅ 人工更新完三張列源名冊後，`authority_master.csv` 由 builder **自動重建**（含守門）

## 六個名冊來源

| 爬蟲 | 主管機關 | 抓什麼 | 覆蓋率限制 |
|---|---|---|---|
| `fetch_banking.py` | 金管會銀行局 | 本國銀行、外國銀行在臺分行、陸銀在臺分行、信用合作社、票券金融、金融控股、專營電子支付（7 份） | 官方頁面完整，無限制 |
| `fetch_sfb.py` | 金管會證期局 | 證券商（改走 TWSE OpenAPI）、期貨業、投信、投顧、證金 | 證券商名稱是簡稱非全銜 |
| `fetch_insurance.py` | 金管會保險局 | 人身／財產／再保險（含外商在臺分公司）、保經代 | **保經代只有公開子集**，全名單須登入 |
| `fetch_boaf.py` | 農業部農業金融署 | 農會信用部、漁會信用部、全國農業金庫 | 官方頁面完整 |
| `fetch_moda.py` | 數位發展部數位產業署 | 第三方支付 AML 登錄名冊（兩份獨立來源） | 官方頁面完整 |
| `fetch_leasing.py` | 台北市租賃商業同業公會 | 融資租賃業會員 | **非主管機關名冊**；會員頁約 38 區塊只有約 14 個是文字，其餘為無 ALT 的 logo 圖檔 |

`source` 欄會如實標記名冊性質。融資租賃那 38 列標的是「租賃公會名錄（非主管機關）」——
因為融資租賃不是特許業，台灣沒有主管機關名單。

## 更新流程

### 步驟 1：抓最新名冊

```bash
py -3.12 -m pip install -r crawlers/requirements.txt   # 第一次才需要

py -3.12 crawlers/fetch_banking.py
py -3.12 crawlers/fetch_sfb.py
py -3.12 crawlers/fetch_insurance.py
py -3.12 crawlers/fetch_boaf.py
py -3.12 crawlers/fetch_moda.py
py -3.12 crawlers/fetch_leasing.py
```

輸出落在 `crawlers/raw/<今天日期>/`，每支都會產一份異動報告，
內容是「與 `crawlers/baseline/` 的既有快照相比，多了誰、少了誰」。

六支都是「HTTP 優先、失敗才 lazy import playwright」，正常情況不需要瀏覽器。
若某個官方站台改版成 JS 渲染或擋爬，該支會回報失敗——**不會靜默產出空名冊**。

### 步驟 2（人工）：判讀異動、更新三張列源名冊

看 `raw/<日期>/*_report.md` 或 `*_diff_report.txt`，對每一筆異動決定：

- **新增機構**（新掛牌、新核准）→ 加列，`status=active`，補統編
- **名稱變更** → 改 `official_name`，`status=renamed`，`aliases` 留舊名
- **併購消滅** → `status=merged`，**不要刪列**（歷史資料還要對得上）
- **退場／除名** → `status=exited`
- **統編補查** → 見步驟 3

三張列源名冊在 `crawlers/masters/`，欄位：
`authority, segment, inst_code, official_name, short_name, aliases, tax_id, tax_id_source, status, notes`

`segment` 只能用 `crawlers/_taxonomy.py` 的 `SEGMENT_TO_GROUP` 定義的 24 個值，
用別的值 builder 會直接報錯。

### 步驟 3（半自動）：補統編

新增的機構通常只有名稱沒有統編。統編是分類的唯一 join 鍵，空值等於這家機構無法對應。

```bash
py -3.12 crawlers/query_pending_taxids.py
```

用 GCIS 商工登記關鍵字查詢補 `masters/tax_id_pending.csv` 裡的待查名單。
命中規則含名稱正規化比對、統編檢查碼驗證；**終止狀態（廢止／解散／撤銷）不自動採用**，
會留在 pending 附候選statuses 供人工確認。解析成功的寫回 `masters/tax_id_lookup.csv`。

> ⚠️ **不要直接執行 `enrich_tax_id.py` 的 main()**。它會用三張列源名冊從零重建 lookup，
> 覆蓋掉既有的 GCIS 查詢成果（現行 1,344 列，其中 233 筆是 GCIS 查得、8 筆人工提供，
> 屬不可重現的資產）。該檔已加旗標保護，但還是別碰。

### 步驟 4：重建 authority_master

```bash
py -3.12 crawlers/build_authority_master.py
```

builder 做的事：
- 校驗三張列源名冊的列數（490／542／311）與 md5 前後一致（只讀不寫守門）
- 用 `tax_id_lookup.csv` 回填留白統編（只填空的，不覆寫既有解析成果）
- 處理兼營雙列（同一法人跨 segment，如彰銀本行 vs 證券部）
- 校驗每列的 `segment` 屬已知值域、且 `industry_group` 與 `SEGMENT_TO_GROUP` 一致
- 輸出 `crawlers/build/authority_master.csv`（deterministic 排序）

**列數守門是刻意的防呆**：如果你更新了列源名冊，列數會變，builder 會停下來報錯。
確認是刻意更新後，把 `SOURCE_INPUTS` 的期望列數改成新值再跑。

#### 移植正確性的實測結果（2026-07-30）

用移植後的 builder 重建，與 `data/authority_master.csv` 這份隨包快照比對：

| 比對項目 | 結果 |
|---|---|
| 列數 | 1,343 vs 1,343 ✓ |
| 內容（視為集合） | **完全相同，一筆不差** ✓ |
| 位元 | 不同（md5 `9dd98a4a…` vs `9276f8c0…`） |
| **內部名單判定結果** | **SHA-256 完全相同** ✓ |

位元不同的原因是**列的排序不同**（隨包快照是 原產線較早的輸出，該檔在
2026-07 期間有經過人工調整）。這不影響任何判定，因為引擎把名冊讀成
「統編 → 列」的字典，兼營多列時用顯式優先序（`金控與銀行 > 證券期貨 > 保險 >
其他金融 > 電支支付`，同序按子分類字典序）決定主分類，**不依賴檔案列序**。

已用內部實務名單實測驗證：換成重建版，輸出的 SHA-256 一字不差。
所以重建出來的檔案可以直接覆蓋 `data/authority_master.csv` 使用。

### 步驟 5：部署給分類器

```bash
copy crawlers\build\authority_master.csv data\authority_master.csv
py -3.12 classify.py --doctor
py -3.12 tests\test_consistency.py
```

## 如果你不想維護爬蟲

完全可以。`data/authority_master.csv` 已經附了一份快照，直接用就好。
代價是名冊會逐漸過期——影響的是：

- 新掛牌的金融機構會落到稅籍碼判定（大類通常仍對，子分類可能不夠細）
- 已併購／退場的機構仍會被當現存（要看 `status` 欄）
- 若拿來當市場分母算滲透率，分母會不準

**最低維護建議**：每季向提供者索取一份新的 `authority_master.csv` 覆蓋即可，
不必自己跑爬蟲。這份檔案只有 446 KB。

## 與原產線的關係

這套爬蟲原本在 `原產線的 fetch_authority/`，移植時做了四件事：

1. 路徑全改走 `crawlers/_paths.py`，不再依賴目錄深度
2. `normalize_tax_id` 複製成 `crawlers/_taxid.py`（原本要 import 原產線的 etl/shared.py，
   那個檔模組層 `import pandas`，為一支純字串函式而依賴 pandas 不合理）
3. `SEGMENT_TO_GROUP`／`GROUP_ORDER` 複製成 `crawlers/_taxonomy.py`
   （原本 import 的檔案在 import 時會 reconfigure stdout 並建目錄）
4. 寫死的日期常數改成 `--run-date` 參數，預設今天

> ⚠️ `_taxid.py` 與 `_taxonomy.py` 是**副本**。如果 原產線那側改了正規化邏輯或
> 分類值域，這裡要同步——兩邊不同口徑會讓同一份來源資料 join 出不同結果。

另外注意：原產線的 ETL 仍依賴它自己那份 `authority_master.csv`。
本包是**副本消費者**，不要反向覆蓋原產線的檔案。
