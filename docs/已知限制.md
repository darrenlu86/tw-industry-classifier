# 已知限制

每一條都有實測依據。承諾這套工具能做什麼之前，請先讀完。

---

## 一、名冊本身的覆蓋天花板（不是程式問題，是官方資料就這樣）

### 1. 政府機關名冊是自願性登錄

`data.gov.tw #44806`／`#166161` 的資料集標題就寫著「**同意開放**統一編號資料集」。
現行 `#44806` 只有 610 筆（僅行政院所屬），實測**查無**：

- 考試院（03807606）— 憲政機關，不屬行政院體系
- 行政院國家發展基金管理會（01031071）— 是基金，非機關
- 雲林縣稅務局（63505302）、新竹市稅務局（98272595）— 地方機關但未登錄

**影響**：這類統編的**分類**由 L3-8 的 N3 名稱規則正確判出（政府機關），
但**官方全銜**查不到，只能用傳入的備用名稱，或人工補進 `rules.py` 的 `FROZEN_NAMES`。

**沒有替代方案**：財政部 OpenAPI 的 24 個端點全數檢視，無任何政府機關端點。

### 2. 保險經紀人名單只有公開子集

全體保險經紀人名單須登入 `intermediary.ib.gov.tw` 才看得到。爬蟲只能抓到
保險局公開的「得於我國經營再保險經紀業務之保險經紀人公司一覽表」PDF 子集
（segment 名稱即標為 `insurance_broker_reinsurance_permitted_subset`）。

現行 `authority_master.csv` 的 542 列保經代來自 `data.gov.tw` 的公會會員名錄
（`#15326` 壽險會員、`#142715` 產險會員），不是主管機關全名單。

### 3. 融資租賃業沒有主管機關名冊

融資租賃不是特許業，沒有主管機關名單。現行 38 列來自
**台北市租賃商業同業公會**會員名錄，`source` 欄如實標記「租賃公會名錄（非主管機關）」。

而且公會的會員名錄頁約 38 個區塊中，只有約 14 個公司名稱是文字，
其餘是**沒有 ALT 屬性的 logo 圖檔**，爬蟲抓不到。這是官方頁面的限制。

### 4. 消費分期／債權平台完全沒有官方名冊（v4：已停止自動判定）

BNPL、消費分期、P2P 債權媒合都不是特許業。唯一的官方訊號是 GCIS 所營事業裡的
「金融機構金錢債權收買業務」（`HZ02010`）。v3 曾有規則 L3-9 拿這個訊號＋名稱訊號詞
雙條件自動判進「其他金融」，**v4 已整層移除**：

**所營事業是「登記可以做什麼」，不是「實際在做什麼」**——這是移除的理由。實例：
願望實現數位金融登記 98 項營業項目，含織布業、皮革整製、糧商業；
亞太普惠登記 40 項，含瘦身美容業、留遊學服務業。雙條件仍會誤判「登記了但沒做」的公司。

現行做法：這類戶落一般企業走稅籍分類（例如稅籍主碼 64 → 金融科技），不再自動歸入
任何金融子類；GCIS 所營事業查詢也已停用，僅保留名稱解析用途。

## 二、資料本身的語意陷阱

### 5. 稅籍檔只含營業中資料

已解散、合併解散、廢止登記的公司在稅籍檔查不到。名稱靠 GCIS 補、
分類靠 `OVERRIDE` 白名單或名稱關鍵字。

**兩者的 miss 語意不同**：稅籍查無回 HTTP 404，GCIS 查無回 HTTP 200 + 空 body。
程式已分開處理，但如果你自己接 API，要注意這點。

### 6. 稅籍行業代號綁第 9 次修訂

現行稅務行業標準分類是第 9 次修訂（基於主計總處第 11 次修正）。
**主計現行已是第 12 次修正**（2026-01-01 生效）。官方切換版本時，
`rules.py` 的 `SUB_BY_MAJOR2` 與 `MAJOR2_LABEL` 需要重新對照。

好消息是只改那張映射表，不用動任何資料或邏輯。

### 7. 統編前導零與 16 碼折半

來源 Excel 被當數字讀會吃掉前導零（`00999340` 變 `999340`）。
`normalize_tax_id()` 會補回 8 碼。另有一種來源端損毀：同一統編重複成 16 碼字串
（`85840188 85840188`），正規化會折半修復；但 token 彼此不同時**絕不猜**，維持原樣。

### 8. 公司登記存續 ≠ 還在營業

GCIS 現行公司登記 812,230 家，稅籍檔的公司類（含分公司）約 757,000 筆，
差的近 6 萬家是「公司登記還在但已無稅籍」。判「這家還在不在」要看稅籍，不是公司登記。

## 三、模式差異

### 9. api 模式必須連外，且外部 API 不通時會中斷

這是刻意設計。API 呼叫失敗時**不會**被當成「查無此統編」——否則同一個統編會因為
當下網路狀況被判成不同分類。重試三次仍失敗就拋 `ApiUnavailable` 中斷整批。

要容忍降級請明確傳 `strict=False`，屆時該筆會標 `confidence=low` 並列入 `provider.degraded`。

### 10. local 模式的 GCIS 名稱解析仍需連外

v4 已移除 L3-9（GCIS 所營事業條件觸發層），GCIS 現在僅剩名稱解析用途
（`provider.company`，稅籍查無時取官方登記名稱與登記狀態），本地端模式在這一步仍會連外。
指定 `--offline` 時該筆改用傳入的備用名稱（沒有備用名稱就是空字串），分類仍照常判定，
不受影響——這個差異會反映在輸出的 `名稱來源` 欄位，不會靜默發生。

### 11. 名稱查不到時，靠名稱的規則會失效

若四個名冊都查無、GCIS 也查無、又沒傳備用名稱，`官方正式名稱` 會是空字串。
此時所有依賴名稱的規則（L3-6 法人前綴、L3-8 名稱關鍵字）都無法命中，
該筆會落到 L4 兜底。

程式會把 `名稱來源` 標成「查無官方名稱」並強制 `confidence=low`，不會假裝判對了。
**建議輸入 CSV 第二欄帶上你手上的名稱**，可以救回這類戶。

## 四、規則的主觀成分

### 12. 白名單與裁決表是人工決定

- `PERIPHERAL`（內建 7 家周邊單位，帶所屬大類）：證交所、集保、期交所、櫃買、碳權交易所
  歸證券期貨；票交所、聯徵中心歸金控與銀行。它們登記型態各異（股份有限公司與財團法人
  並存），稅籍碼也分散，所以用統編白名單認定，而不是規則推導。v4 起周邊單位不再歸
  政府機關，改掛所屬金融大類的「周邊單位」子類。組織可在本地例外檔 `peripheral_extra`
  追加（不進版控），目前筆數見 `classify.py --doctor`。
- `OVERRIDE`（16 筆）：包含一條純業務口徑的決定（元大金控歸證券，理由是業務往來主體
  為元大證券而非銀行端）。這類決定換一家公司用可能就不適用。

兩張表都在 `rules.py`，每筆都附理由與裁決日期。**接手的人應該重新檢視這兩張表**
是否符合自己的業務口徑。

### 13. 八大類是自訂的，不是官方分類

「金控與銀行／證券期貨／保險／租賃／電支支付／政府機關／教育與法人／一般企業」
是為了業務分析定的值域，不對應任何官方標準分類。
金控與銀行／證券期貨／保險三類的**子分類**沿用金管會名冊的 segment（事實層）；
租賃只認租賃公會名錄會員，子分類單一「融資租賃資融」；
其餘（尤其一般企業的 9 個子類）是自訂映射。

## 五、交付範圍

### 14. 不含任何客戶名單

`input/taxids_sample.csv` 是公開機構的示範資料。`data/authority_master.csv` 是
公開的金融機構名冊（1,343 家主管機關監理對象），不含客戶資訊。

### 15. 爬蟲產線有一段人工缺口

**這是最重要的一條**：六支爬蟲能抓到最新官方名冊並產出異動報告，
但「異動 → 三張列源名冊 → authority_master.csv」中間**沒有自動化路徑**。
詳見 [名冊維護與爬蟲](名冊維護與爬蟲.md)。

承諾更新頻率之前務必讀那一份。

### 16. 上游原產線的值域與本 repo 已刻意分岔，尚未收斂

上游原產線（`etl/process_industry.py` 與其客戶主檔）的分類值域仍是
「其他金融」（v3 舊版），本 repo 的事實層（`crawlers/_taxonomy.py`）已依 v4 改成
「租賃」＋周邊單位掛金融大類。兩邊目前**刻意**不同步——這是已知現況，同步時程與
方式屬另案，尚未定案。跨這兩個系統對資料前，先確認雙方用的是哪一版值域。
