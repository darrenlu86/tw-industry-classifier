## 前五個：一行指令更新

```bash
py -3.12 core/fetch_bulk_data.py              # 只補缺檔或超過 30 天的檔
py -3.12 core/fetch_bulk_data.py --force      # 全部重抓
py -3.12 core/fetch_bulk_data.py --check      # 只檢查來源可達與本地新舊
py -3.12 core/fetch_bulk_data.py --max-age 7  # 改成 7 天門檻
py -3.12 core/fetch_bulk_data.py --only tax_registry   # 只抓稅籍
```

每個檔下載後會驗證三件事才取代舊檔：檔案大小下限、內容可解析、列數落在預期區間。
**任何一項不過就保留舊檔**並在畫面標「失敗」——離線可用比資料新鮮重要。
結果寫進 `data/_fetch_log.json`。

下載網址的解析順序是「財資中心固定網址 → data.gov.tw API 動態解析」。
第 4、5 個來源沒有固定網址（是雜湊檔名，會換），所以一律走 data.gov.tw API 解析。
實測 `#166161` 的下載端點偶爾回 502，重試三次仍失敗就會保留舊檔。

### 更新稅籍後要重建索引

```bash
py -3.12 core/build_tax_index.py --check      # 檢查索引是否比稅籍檔新
py -3.12 core/build_tax_index.py              # 重建（約 2 分鐘）
```

索引不重建不會出錯，但會拿舊資料回答。`--check` 會明確告訴你索引比稅籍檔舊。

## 各來源的實際內容（實抽驗證）

### 1. 稅籍登記 BGMOPEN1

只含**營業中**的營業人。組織別分布（171 萬筆實掃）：

| 組織別 | 筆數 | 佔比 |
|---|---|---|
| 獨資 | 850,073 | 49.7% |
| 有限公司 | 538,376 | 31.5% |
| 股份有限公司 | 179,257 | 10.5% |
| 其他 | 53,133 | 3.1% |
| 合夥 | 41,864 | 2.4% |
| 本國公司分公司 | 39,748 | 2.3% |
| 外國公司在台分公司 | 5,344 | 0.3% |
| 合作社／有限合夥／其他 | 2,138 | 0.1% |

每戶有 1 主 3 副行業代號（稅務行業標準分類第 9 次修訂，6 碼）。
**主碼是稽徵機關依實際營業核定的**，這是本工具判產業的主要依據。

單筆 API：`GET https://eip.fia.gov.tw/OAI/api/businessRegistration/{統編}`
回傳 `businessNm`（名稱）、`businessType`（組織別）、`industryCd`＋`industryCd1~3`（1 主 3 副）。
查無回 HTTP 404。

### 2. 非營利事業機關團體名冊

國稅局受理教育／文化／公益／慈善機關團體申請扣繳單位統編的建檔資料。
補上「財團法人與公益團體沒有公開統編名冊」這個缺口。

單筆 API：`GET https://eip.fia.gov.tw/OAI/api/nonBusinessUnit/{統編}` → `unitNm`

### 3. 全國各級學校統編

含公私立各級學校。注意 `modifyReasonNm` 可能是「一般註銷」，代表該統編已停用但仍在名冊裡。

單筆 API：`GET https://eip.fia.gov.tw/OAI/api/schoolBanData/{統編}` → `unitNm`

### 4／5. 政府機關統編（兩份）

**這兩份資料集的標題就寫著「同意開放」——是自願性登錄，本質上收不全。**
實測現行 `#44806` 只有 610 筆（行政院所屬），考試院（憲政機關，非行政院體系）、
雲林縣稅務局、新竹市稅務局都不在裡面。

財政部的 OpenAPI 規格（`eip.fia.gov.tw/OAI/v2/api-docs`，24 個端點全數檢視）
**沒有任何政府機關端點**；財政部本身（03732303）與勞保局（03769808）在稅籍與非營業單位
兩支 API 都回 404。所以機關統編只存在於這兩支 CSV，兩種模式都必須帶。

名冊收不到的機關由分類規則 L3-8 的 N3 補（名稱含 院／署／局／處／委員會／稅務局／管理會 等），
但那只解決「分類」，**官方全銜仍需人工補進 `rules.py` 的 `FROZEN_NAMES`**。

### 6. 金管會權威名冊 authority_master.csv

金融四類（金控與銀行、證券期貨、保險、電支支付）與租賃的分類事實來源。
**1,343 列資料、1,341 個唯一統編**——差的 2 個是同一法人跨 segment 的兼營列：

| 統編 | 兩列內容 |
|---|---|
| `51811609` | 彰化商業銀行（本國銀行）／彰化商業銀行證券部（證券商） |
| `21222871` | 法商法國巴黎銀行台北分行（外國銀行在臺分行）／台北分公司（證券商） |

兼營時引擎依 `金控與銀行 > 證券期貨 > 保險 > 租賃 > 電支支付` 取主分類，
同優先序再按子分類字典序——所以不會因為檔案列序不同而判出不同結果。

**非公開下載檔**，見
[名冊維護與爬蟲](名冊維護與爬蟲.md)。

沒有這個檔，金融機構會退到稅籍碼判定——金融特許碼（如 641211 本國銀行）仍判得對大類，
但子分類會不夠精確（例如分不出「外國銀行在臺分行」與「本國銀行」）。
所以 `classify.py` 預設把它列為**必需**，缺檔會直接報錯而不是靜默降級。

## GCIS 商工登記（條件觸發，非固定資料源）

一個用途，不是整批下載，而是需要時查單筆：

- **補名稱**：稅籍查無時（已解散、廢止、外商在台）取官方登記名稱與登記狀態。
  端點 `5F64D864`（公司登記基本資料-應用一）。

免金鑰。**查無時回 HTTP 200 + 空 body**，與稅籍的 404 語意不同，程式已分開處理。
查詢結果會快取在 `data/_gcis_cache.json`。

（v4 已移除）原規則 L3-9 曾用 GCIS 所營事業查詢「金融機構金錢債權收買業務」
（代碼 `HZ02010`／`HZ02020`，端點 `236EE382`）自動判定消費分期／債權業者，
現已整層移除，該類戶落一般企業走稅籍分類，GCIS 僅剩上面的名稱解析用途。

## 更新頻率建議

| 情境 | 建議 |
|---|---|
| 只查既有客戶、分類穩定 | 稅籍每月、其餘每季 |
| 會查新客戶、要判最新設立的公司 | 稅籍每週或每日 |
| 要當市場分母算滲透率 | 金管會名冊每季必更（機構掛牌／併購／退場都影響分母） |
| 只是臨時查幾筆 | 用 `--mode api`，不需維護任何檔案 |

`data/_fetch_log.json` 記錄每次下載的時間與結果；每筆查詢輸出也帶 `資料版本` 欄位
（各資料檔的 mtime），稽核時可回推當時用的是哪個快照。
