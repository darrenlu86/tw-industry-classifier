# data/ — 資料層

這個目錄的資料檔**不在版控裡**（見 `.gitignore`）。clone 下來之後是空的，需要自己準備。

## 五個公開資料源：一行指令取得

```bash
py -3.12 core/fetch_bulk_data.py
```

| 檔案 | 內容 | 大小 | 官方更新 | 來源 |
|---|---|---|---|---|
| `BGMOPEN1.zip` | 財政部稅籍登記全量（約 171 萬筆營業人） | 63 MB | 每日 | [data.gov.tw #9400](https://data.gov.tw/dataset/9400) |
| `BGMOPEN99.csv` | 非營利事業機關團體名冊 | 12 MB | 每月 | [#34147](https://data.gov.tw/dataset/34147) |

全部免金鑰。下載後會驗證檔案大小、可解析性、列數區間，任一項不過就保留舊檔並回報。

**api 模式只需要後兩個**（政府機關是唯一沒有單筆查詢 API 的資料源）；
前三個在 api 模式改打財政部的單筆端點。

## 第六個：`authority_master.csv` 需要自己建

金管會權威名冊，是金融四類（金控與銀行、證券期貨、保險、電支支付）
與其他金融的分類事實來源。**不是公開下載檔**——它由六個主管機關名冊爬下來後組裝。

三條路：

1. **自己建**：`crawlers/` 有完整產線，見 [`docs/名冊維護與爬蟲.md`](../docs/名冊維護與爬蟲.md)。
   但要注意那份文件的第一節：抓取可以自動化，「異動 → 名冊」中間有一段人工歸併。
2. **向提供者索取快照**：只有 446 KB，每季更新一次即可。
3. **不用它**：分類器會退到稅籍碼判定。金融特許碼（如 `641211` 本國銀行）仍判得對大類，
   但子分類會不夠精確（例如分不出「外國銀行在臺分行」與「本國銀行」）。
   目前 `classify.py` 預設把它列為必需，缺檔會直接報錯而非靜默降級——
   這是刻意的，避免你以為分類是準的。

## 可選：稅籍 sqlite 索引

```bash
py -3.12 core/build_tax_index.py
```

產生 `tax_index.sqlite`（約 243 MB），讓本地端單筆查詢從約 15 秒變毫秒級。
不建也能跑，只是慢。稅籍檔更新後記得重建（`--check` 會告訴你索引是否過期）。

## 快取檔

`_gcis_cache.json`、`_api_cache.json`、`_fetch_log.json` 是執行產生的，可以隨時刪掉。
刪了只是下次要重新查。**快取會含查詢過的統編**，所以也不進版控。
