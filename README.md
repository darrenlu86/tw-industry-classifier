# industry_classifier — 統編查產業分類

輸入一個統一編號，回傳**官方登錄的正式名稱**與**產業分類（產業大類＋產業子類）**，並附上判定依據。

```
$ py -3.12 classify.py 22099131

  統一編號     ：22099131
  官方正式名稱   ：台灣積體電路製造股份有限公司
  產業大類     ：C 製造業
  產業子類     ：26 電子零組件製造
  大分類（僅供參考）：一般企業
  子分類（僅供參考）：製造
  分類依據詞    ：稅籍大類 26 電子零組件製造
  分類依據層    ：L3 稅籍碼表
  判定規則     ：L3-7 稅籍大類26 電子零組件製造
  名稱來源     ：稅籍(財政部)
  信心       ：medium
  查詢模式     ：本地端全檔
  資料版本     ：稅籍=2026-07-30 非營利=2026-07-30 學校=2026-07-30 …
```

（`資料版本` 實際會列出每個資料檔的快照日期，此處省略尾段。空值欄位不印，
所以這一筆看不到 `登記狀態` 與 `統編備註`。）

產業大類／產業子類為**定版單軌**：有官方執照或法定身分者沿用身分分類
（金控與銀行、證券期貨、保險、租賃、電支支付、政府機關、教育與法人、執行業務者）；
一般企業（名冊查無執照）改由稅籍主行業代號歸 A–S 行業別，不再是看不出內容的桶。

全程**不使用 AI 判斷、不需人工介入**。163 條通用規則的有序瀑布，首次命中即定案，最後一層兜底。

**任何輸入都有明確輸出**（v5）：8 碼統編、F 碼、P 碼、統編欄空白、格式異常，
每一種都有對應的分類值與可稽核的依據詞，不會靜默丟掉、也不會拿兜底值假裝判對了。

同一份輸入搭配同一份資料快照，任何人執行都會得到**完全相同**的結果——這點有測試驗證，
不是宣稱（見「驗收」一節）。

---

## 兩種查詢模式，選一個

| | **local 本地端** | **api 線上查詢** |
|---|---|---|
| 資料 | 自己先下載全檔 **約 320 MB** | 只需名冊小檔 **約 580 KB** |
| 外網 | 可完全離線（`--offline`） | 必須連外 |
| 速度 | 建索引後單筆毫秒級；整批數百筆約 3 秒 | 每筆 1–3 次 API 呼叫，數百筆約 2 分鐘 |
| 適合 | 整批跑名單、接成內部服務、無外網環境 | 臨時查幾筆、不想維護大檔 |
| 資料新鮮度 | 取決於你多久重抓一次 | 永遠是官方當下的資料 |

**兩種模式共用同一個判定引擎**（`core/engine.py`），差別只在資料怎麼取得。
實測同一份清單，兩種模式**逐欄完全相同**。

不確定選哪個就別選——預設 `--mode auto` 會自己判斷：全檔在就走 local，不在就走 api。

## 快速開始

需要 **Python 3.12**。分類器本身**零第三方套件**，只用標準庫。

### A. 先把資料準備好

`data/` 目錄**不含任何資料檔**（見 [`data/README.md`](data/README.md)）——公開資料源太大不適合進版控，
金管會權威名冊則是彙整成果。

```bash
# 五個公開資料源，免金鑰，一行搞定
py -3.12 core/fetch_bulk_data.py

# 檢查就位狀況（會告訴你還缺什麼、該怎麼補）
py -3.12 classify.py --doctor
```

`data/authority_master.csv`（金管會權威名冊）需要自己建或向提供者索取，
詳見 [`data/README.md`](data/README.md)。它決定金融四類的子分類精確度。

`data/listed_master.csv` 與 `data/listed_industry_map.csv`（上市櫃名冊）是**選用**的，
由 `crawlers/fetch_listed.py` 產出；缺檔時 L2-5 那一層整層跳過，其餘照常。

### B. api 模式（只需名冊小檔＋外網）

```bash
py -3.12 classify.py --mode api 22099131
```

只需要 `gov_central.csv`、`gov_local.csv`（`fetch_bulk_data.py` 會下載）
與 `authority_master.csv`，合計約 580 KB。

### C. local 模式（可離線、整批快）

```bash
# 建稅籍索引（可選，約 2 分鐘／243 MB，讓單筆查詢從 15 秒變毫秒）
py -3.12 core/build_tax_index.py

# 跑名單
py -3.12 classify.py --input input/taxids_sample.csv --output output/結果.csv
```

輸入 CSV 只要**第一欄是統編**就行，有沒有表頭都可以；第二欄若有名稱會當備用名。

### D. 統編欄可以放什麼（v5）

| 輸入 | 結果 | 說明 |
|---|---|---|
| 8 碼數字 | 走完整規則瀑布 | 不足 8 碼的純數字會自動補前導零 |
| `F` 開頭（如 `F000138`） | 境外法人（無台灣登記） | 命中即終結，**不進任何名冊、稅籍、名稱層** |
| `P` 開頭 | 個人戶 | 同上 |
| 空白／`N/A`／`-` | 查無統編歸戶表（名稱完全比對）→ 命中依表值，查無歸「無法分類」 | 這類列**不會被丟掉**，第二欄請帶上名稱 |
| 其他格式 | 無法分類，`統編備註` 標「統編格式異常」 | 這是叫人去修輸入檔的訊號，不是分類結果 |

前綴表在 `core/rules.py` 的 `UID_PREFIX`，是可設定的對照表——
你的來源系統如果用別的前綴，改那一個 dict 就好。

### E. 輸出欄位

| 欄位 | 說明 |
|---|---|
| `統一編號` | 正規化後的值（8 碼數字會補前導零；F／P 碼原樣保留） |
| `官方正式名稱` | 官方登錄名稱，非帳務系統名 |
| `產業大類` / `產業子類` | **定版單軌**，見下節 |
| `大分類` / `子分類` | 身分軌原值，供稽核與八欄版並排比對 |
| `分類依據詞` | 一句話講清楚為什麼這樣分，例如「稅籍大類 26 電子零組件製造」 |
| `分類依據層` | 命中哪一層（L0 統編解析／L1 特殊規則／L2 權威名冊／L3-A 制度性名稱／L3 稅籍碼表／L3 名稱關鍵字／L4 兜底） |
| `判定規則` | 完整規則編號與條件 |
| `名稱來源` | 名稱從哪個名冊來 |
| `登記狀態` | GCIS 或凍結表的登記狀態原值（非核准者信心自動降 low） |
| `信心` | high／medium／low，low 代表要人工看一眼 |
| `統編備註` | 統編被修正、格式異常、離線未查等註記 |
| `查詢模式` / `資料版本` | 稽核用：哪個模式、資料快照日期 |

## 值域

| 大分類 | 子分類 |
|---|---|
| 金控與銀行 | 本國銀行、外國銀行在臺分行、陸銀在臺分行、信用合作社、農業金庫、郵政儲匯（兼營簡易壽險）、金融控股、農漁會信用部、票券金融、周邊單位 |
| 證券期貨 | 證券商、期貨商、投信、投顧、證券金融、周邊單位 |
| 保險 | 人身保險、財產保險、再保險、保險經紀人公司、保險代理人公司、外商保險在臺分公司、周邊單位 |
| 租賃 | 融資租賃資融 |
| 電支支付 | 專營電子支付、第三方支付 |
| 政府機關 | 政府機關 |
| 教育與法人 | 學校、財團法人與公協會 |
| 一般企業 | 資訊服務與軟體、批發零售與通路、製造、專業服務、觀光餐旅、不動產與營建、金融科技、醫療、其他、未細分 |
| 執行業務者（非營業人） | 會計師事務所、律師事務所、建築師與技師事務所、記帳士與報稅代理、其他執行業務者 |
| 境外法人（無台灣登記） | （空白） |
| 個人戶 | （空白） |
| 無法分類 | （空白） |

值域定義在 `core/rules.py` 的 `SUBGROUPS`，每次執行都會自我檢查有無越界。

**單軌另有兩個專屬值**，不屬於上表（只會出現在 `產業大類`，身分軌仍是一般企業）：

- `未登記（稅籍查無）`——稅籍查無，且上市櫃名冊與 GCIS 狀態都沒答案
- `已解散（歷史戶）`——GCIS 登記狀態含解散／廢止／撤銷／撤回

幾個值域上的取捨：
「租賃」大類＝租賃公會名錄會員，子分類單一「融資租賃資融」；非會員的融資業者一律落一般企業走稅籍分類。
「周邊單位」是金控與銀行／證券期貨／保險三大類各自的子分類，掛白名單機構所屬的金融大類。
農會信用部與漁會信用部在金管會名冊是兩個 segment，載入後正規化併成「農漁會信用部」。

## 判定流程

```
統編 → 正規化（補前導零）
  │
  ├── L0 統編解析（v5，在一切之前）
  │     首碼命中 UID 前綴表 → 個人戶／境外法人（終結，不再往下）
  │     統編空白 → 無統編歸戶表（名稱完全比對）→ 查無歸「無法分類」
  │     其他格式 → 無法分類＋統編備註「統編格式異常」
  │     8 碼數字 → 續走
  │
  ├── 步驟一：取官方正式名稱
  │     稅籍 → 機關名冊 → 學校名冊 → 非營利名冊
  │     → 存量凍結表 → 金管會名冊 → GCIS 商工登記
  │
  └── 步驟二：判分類（首次命中即定案）
        L1   特殊規則    統編修正 → 周邊單位白名單 → 存量裁決例外（可為空）
        L2   權威名冊    金管會 → 機關 → 學校 → 非營利
        L3-A 制度性名稱  醫院／診所 → 學校 → 專業別事務所（v5，**早於稅籍層**）
        L3-B 稅籍碼表    醫療碼 → 金融六碼精確 → 金融特許四碼
                        → 教育法人二碼 → 法人名稱前綴
        L3-7 大類映射    稅籍主碼前二碼 → 一般企業的 9 個子分類
        L3-C 名稱關鍵字  僅稅籍查無時啟用，14 條有序規則（編號到 N15，N5 已移除留缺口）
        L4   兜底        一般企業／未細分（標 confidence=low）

判完身分軌之後，單軌的產業大類／產業子類這樣決定：
        身分軌命中（含 L0 的新值）→ 直接沿用
        L3-A 醫療命中            → Q 醫療保健及社會工作服務業／86 醫療保健服務
        一般企業                 → 稅籍主行業碼（A–S）
                                   → 稅籍查無時：L2-5 上市櫃名冊
                                   → 都沒有：未登記（稅籍查無）
        最後 L3-D 覆蓋           → 登記狀態含 解散／廢止／撤銷／撤回
                                   → 已解散（歷史戶），**不分身分軌群組**
```

L3-D 是最後套用、會蓋掉前面結果的一層：已廢止的銀行與已解散的公司，在
「這家還在不在」這個問題上是同一件事。身分軌（`大分類`／`子分類`）仍保留原群組
值供稽核——那回答的是「它是什麼」。同一列兩欄不同值是刻意的，不是矛盾。

L3-D 有一道**統編重號守門**：官方名稱若出自機關／金管會／上市櫃等其他名冊，
要 GCIS 同號記錄的名稱對得上才採信其狀態。統編會重號，現存機關的統編撞上
一家已解散的歷史公司是真實發生過的事。對不上就不改標，並在 `統編備註` 寫明。

**為什麼 L3-A 要排在稅籍之前**：醫院、學校的稅籍主行業碼常常是附屬營業碼——
校舍出租登記成不動產經營、附設停車場登記成運輸輔助。先問稅籍會把本業整個蓋掉
（實例：某大學稅籍主碼 68，v4 判成不動產業）。醫院、診所、大學、會計師事務所
都是受名稱管制的法定名銜，精確度足以放在稅籍之前。

代價是要防呆，L3-A 有四道：整層前置排除法人與公協會、公司／店家型後綴排除、
逐規則關鍵詞排除（獸醫、美容補習）、詞尾錨定。
泛用的「事務所」尾綴則**刻意放在稅籍之後**——裱框事務所、婚禮事務所這類有稅籍的店家
不能被標成「非營業人」。

完整規則明細（163 條通用規則）：

```bash
py -3.12 core/emit_rule_table.py     # 產出 docs/分類邏輯表.csv 與 .md
```

## 八欄版對照表（身分軌＋行業軌）

除了 `classify.py` 的標準輸出，`emit_eight_column.py` 可產出「身分軌＋行業軌」並列的
八欄版對照表：身分軌是本文件的身分分類判定結果（一般企業子類留空，
產業資訊改由行業軌回答）；行業軌是稅籍主行業代號直查 `rules.SECTION_BY_MAJOR2`
（稅務行業標準分類第 9 次修訂 A–S 十九大類），兩軌互相獨立。
行業軌只認稅籍主碼——唯一的例外是官方四個來源全查無的戶，可由 L1-3 人工填值，
見 [`exceptions/README.md`](exceptions/README.md) 的 `override` 一節。

```bash
py -3.12 emit_eight_column.py --in <輸入.xlsx> --out <輸出.xlsx>
```

輸入 xlsx 需含「統一編號」欄；輸出兩個分頁：主表八欄（列序與輸入一致）與「周邊單位」
白名單全列（內建＋本地例外檔追加）供複核。產物含名單資料，一律寫到 `output/`
（已被 `.gitignore` 排除，不會進公開 remote）。

注意：八欄版的行業軌是**純稅籍**的，不套 L2-5／L3-D 那兩層 fallback——
要看含 fallback 的結果請用單軌版或 `classify.py`。

## 單軌版對照表（定版：每戶一組產業大類＋產業子類）

`emit_single_track.py` 產出定版的六欄對照表——欄位樣貌同原始對照表，
但只有一組產業分類（合併邏輯在 `core/engine.py` 的 `query()`，
與 `classify.py` 單筆查詢輸出一致）。

```bash
py -3.12 emit_single_track.py --in <輸入.xlsx> --out <輸出.xlsx>
```

輸出六欄：統一編號／官方正式名稱／產業大類／產業子類／分類依據詞／原始資料產業別，
兩個分頁（主表＋周邊單位）；同樣一律寫到 `output/`。

## 驗收

```bash
py -3.12 -m pytest tests/          # 規則與值域（43 項，不需外網）
py -3.12 tests/test_consistency.py # 重現性與兩模式一致性
```

`test_consistency.py` 跑五項檢查，全部通過才算可交付：

1. **重現性**：local 連續兩次 SHA-256 相同
2. **冷啟動**：刪掉快取重跑，結果仍相同
3. **輸入順序無關**：打亂輸入順序，結果仍相同
4. **值域**：每筆子分類都在合法值域內
5. **兩模式一致**：local 與 api 逐欄相同（排除「查詢模式／資料版本」兩欄）

無外網時加 `--skip-api`，只跑前四項；連 GCIS 名稱解析都不要打就再加 `--offline-local`。

pytest 收得到的兩個檔：

- `tests/test_v4_golden.py`——v4 值域結構（大類／子類、已移除規則是否徹底移除）
  ＋公開個體 golden 個案
- `tests/test_v5_golden.py`——v5 的 L0 統編解析、L3-A 制度性名稱與四道防呆、
  單軌 fallback（L2-5／L3-D）、新值域。規則測試用合成 provider 與合成名冊，
  **不依賴 `data/` 下的真檔**；只有 3 項真資料個案會在缺檔時跳過。

golden 個案一律只用公開個體（上市公司、公立私立學校、法定金融基礎設施），
F／P 案例用合成值。

## 要改規則的時候

規則分兩層，改的地方不同。

### 通用規則 → `core/rules.py`

純資料（零 import、零路徑），任何人都適用的部分：

- 稅籍分類改版了 → 改 `SUB_BY_MAJOR2` 與 `MAJOR2_LABEL`
- 要加子分類 → 先加進 `SUBGROUPS` 值域，否則值域自我檢查會擋下來
- 制度性名稱規則 → `INSTITUTIONAL_RULES`（順序即優先序），
  防呆清單在 `CORP_SUFFIX_EXCLUDE`、`CORP_SUFFIX_GUARD_RULES`、`INSTITUTIONAL_KEYWORD_EXCLUDE`
- 一般名稱關鍵字 → `NAME_RULES`（順序即優先序），尾綴排除在 `NAME_RULE_SUFFIX_EXCLUDE`
- 統編前綴 → `UID_PREFIX`

**改名稱規則前請先實掃母體**：`core/engine.py` 的 `_match_institutional()` 可以直接拿去
掃稅籍全檔，數出一條規則會命中幾筆、命中的是什麼。v5 的四道防呆全部是這樣掃出來的
——用想的會漏掉「動物醫院」「大學城自助餐」這種。

### 存量裁決紀錄 → `exceptions/local_exceptions.json`

先講清楚定位：**分類 pipeline 對未來的新客戶不依賴人工裁決**。丟一個沒看過的統編進來，
答案由官方名冊、稅籍碼與名稱規則決定；例外表是空的也照樣跑，不會少一塊。

這個檔記的是**回溯既有名單時留下的一次性裁決紀錄**——整理存量資料時遇到的帳務佔位碼、
已解散但仍在名單裡的舊戶、官方名冊分類與自身業務口徑不同的個案，當時查證的結論記在這裡，
下次重跑同一批名單不用重查。六張表：統編修正、追加周邊單位、已裁決例外、凍結名稱、
凍結登記狀態、無統編歸戶。格式見 [`exceptions/README.md`](exceptions/README.md)。

它隨存量名單長，不隨新客戶長。**空的例外表不是待辦事項。**

**為什麼分開放**：這類裁決的理由通常涉及業務往來關係或對特定機構的內部研究。
混在通用規則裡會讓規則檔看起來像一份客戶清單，而且換一個組織使用時本來就該重新檢視，
不該照抄別人的裁決。

### 改完之後

```bash
py -3.12 -m pytest tests/              # 規則與值域
py -3.12 tests/test_consistency.py     # 重現性
py -3.12 core/emit_rule_table.py       # 讓 docs/分類邏輯表 跟著更新
```

規則表與文件是同一份來源生成的，不會出現「文件寫的跟程式跑的不一樣」。

## 季度複核

日常查詢是全自動的：新客戶丟進來就有答案，不需要人工介入、不依賴任何預先建好的表。
但每一批跑完都會留下一小撮官方資料當下答不出來的戶——季度複核就是**每三個月
把這撮殘量清一次**，不是常設的人工環節。

**複核對象**＝批次輸出中 `產業大類` 為「未登記（稅籍查無）」或「無法分類」的列，
也就是 `信心=low` 清單的主體。

```bash
# 從批次輸出撈複核清單
py -3.12 -c "import csv,sys; [print(r['統一編號'], r['官方正式名稱'], r['產業大類']) \
  for r in csv.DictReader(open(sys.argv[1],encoding='utf-8-sig')) \
  if r['產業大類'] in ('未登記（稅籍查無）','無法分類')]" output/結果.csv
```

（用 Excel 的話：開輸出檔，`信心` 欄篩 `low`，或 `產業大類` 欄篩那兩個值。）

四個步驟，順序有意義：

1. **先更新官方資料**——`py -3.12 core/fetch_bulk_data.py`，
   金管會名冊等另見 [`docs/名冊維護與爬蟲.md`](docs/名冊維護與爬蟲.md)。
2. **重跑名單**。這一步會自動解掉一批：「未登記」裡有相當比例是**新設公司的稅籍時間差**
   ——公司登記好了、稅籍檔還沒收錄，等官方資料追上就有答案了。**先做這兩步再看人，
   否則會把時間差當成待查案件在查。**
3. **仍殘留的逐筆人工檢視**。到這一步還查無的，才是真的需要人看：帳務系統的佔位碼、
   已解散的舊戶、名稱缺漏到所有規則都咬不住的列。
4. **檢視結論屬存量裁決者，記入 `exceptions/local_exceptions.json`**，附理由與日期。
   這是一次性紀錄，讓下次重跑同一批名單不用重查——不是在建一張要持續餵養的表。
   格式見 [`exceptions/README.md`](exceptions/README.md)。

同一份表裡已有的存量裁決也在這時候回頭看一次：併購、更名、法規變動都會讓當初的判斷失效。

## 已知限制

摘要如下，完整版見 [`docs/已知限制.md`](docs/已知限制.md)：

1. **機關名冊是自願性登錄**（`#44806`／`#166161` 標題就寫「同意開放」），收不全。
   考試院、部分地方稅務局都不在裡面，只能靠名稱關鍵字規則（N3：院／署／局／處／委員會）補。
2. **稅籍檔只含營業中資料**。已解散、廢止的公司查不到；v5 的 L3-D 會用 GCIS 登記狀態
   判「已解散（歷史戶）」，但那一層需要連外，`--offline` 時會跳過並在統編備註標記。
3. **稅籍行業代號綁第 9 次修訂**（基於主計第 11 次修正）。主計現行已是第 12 次，
   官方改版時要改 `rules.py` 的映射表。
4. **金管會名冊的保經代與融資租賃有官方層面的覆蓋天花板**：
   全體保險經紀人名單須登入才看得到、租賃公會會員頁有一半是無 ALT 的 logo 圖檔。
5. **L3-A 排在稅籍之前是有代價的判斷**。防呆擋不住的殘留誤收（例如大學附設停車場、
   校門口以「大學城」為名的店家）仍存在，A3(b) 一律標 medium 進複核。
6. **「無法分類」與無統編歸戶表是人工缺口**，沒有官方資料源可以自動補。
7. **交付包不含任何名單資料**。`input/taxids_sample.csv` 是公開機構的示範資料。
